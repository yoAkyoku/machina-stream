# Kafka event path with PostgreSQL projections

For v1, HTTP ingress validates telemetry and acknowledges acceptance only after Kafka confirms the keyed event on `telemetry.events.v1`; an independent Python processor writes immutable event history and the latest machine/alert projections to PostgreSQL. Keep `machine_id` as the Kafka key and use at-least-once delivery with idempotent database effects, committing offsets only after a durable database commit or an acknowledged write to `telemetry.events.v1.dlq`. This preserves a demonstrable recovery path without claiming end-to-end exactly-once behavior; a single local broker is for reproducible development and is not high availability. Pin the local broker to Kafka 3.9.2 for the `aiokafka` client baseline: the client project has documented protocol-compatibility gaps with Kafka 4.x, so broker upgrades must be revalidated rather than assumed safe.
